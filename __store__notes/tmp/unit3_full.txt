3.2 Asynchronous Programming, Callbacks and Promises  
 
3.2.1 Introduction  
JavaScript programs often perform operations that do not produce an 
immediate result. For example, a website may request student details 
from a server, wait for an online payment response, load an image, or 
obtain product information from a database. Some of these operations 
may require a few milliseconds or several seconds to complete.  
 
If JavaScript stopped the entire webpage until every such operation 
was completed, the website could become slow and unresponsive. 
Asynchronous programming  allows time-consuming operations to proceed 
without unnecessarily blocking the remaining program.  
To understand asynchronous programming, beginners should first 
understand the difference between synchronous and asynchronous  
execution. 
 
3.2.2 Synchronous Programming  
Definition: Synchronous programming is a method of program execution 
in which statements are executed in sequence, and each operation is 
completed before the next operation proceeds.  The execution order 
normally follows the order in which the statements appear in the 
program. If one operation takes a long time to complete, subsequent 
operations may have to wait. Synchronous execution is simple to 
understand and is suitable for operati ons that produce results 
immediately. 
 
Simple Example

3.4 XML Syntax and Namespaces  
3.4.1 Introduction

applications can interpret the document cor rectly. 
When XML documents combine information from different applications, 
the same element name may be used with different meanings. XML 
namespaces solve this problem by uniquely identifying groups of XML 
elements.

3.6 AJAX: Introduction and Working Principle  
3.6.1 Introduction  
Traditional webpages commonly follow a complete request –response cycle. 
When a user submits a form or requests new information, the browser 
sends a request to the server and may reload the entire webpage to 
display the response. Repeated page reloads can m ake an application 
feel slower and interrupt the user's interaction with the page.  
AJAX provides a different approach. JavaScript can communicate with 
a server in the background, receive the required information, and update 
only the necessary part of the webpage. This allows websites to 
provide a faster and more interactive user experience.  
For example, when a student enters a registration number on a result 
portal, the result can be displayed below the search box without loading 
an entirely new page.  
 
3.6.2 AJAX  
Definition: AJAX stands for Asynchronous JavaScript and XML and 
refers to a web -development technique in which JavaScript communicates 
with a server asynchronously and updates selected parts of a webpage 
without requiring a complete page reload.  AJAX is not a separate 
programming language or software product; it is an approach that 
combines existing web technologies. JavaScript controls the communication 
and webpage update, while data may be exchanged using XML, JSON, 
text, or other formats. Alth ough the name contains XML, modern 
AJAX applications frequently use JSON.  
Traditional approach:  
Browser → Request → Server → New Complete Page  
  FACULTY NAME:  A VINASH PAL LIDLAAN , ASSISTANT PROFESSOR, DEPT:  AI 
 
 
AJAX approach:  
Browser → Background Request → Server → Data → Update Required 
Section 
 
Scenario 
Consider an e -commerce website. A customer selects a different product 
category. 
Without AJAX, the complete webpage may reload to display the selected 
products. 
With AJAX, JavaScript can request only the required product 
information and update the product section while the header, menu, and 
other webpage content remain unchanged.  
 
3.6.3 Brief History of AJAX  
The technologies used for AJAX existed before the term itself became 
popular. Browser -based asynchronous communication became practical 
through mechanisms that eventually developed into the XMLHttpRequest 
interface. 
In 2005, Jesse James Garrett popularized the term AJAX in the 
article Ajax: A New Approach to Web Applications . He used the term 
to describe web applications that communicate with servers 
asynchronously and update their interfaces dynamically instead of 
repeatedly loading complete webpages.  
Early AJAX applications commonly exchanged XML data. Later, JSON 
became very popular because it is compact and convenient to process in 
JavaScript. Modern applications may use either XMLHttpRequest or the 
newer Fetch API to perform AJAX -style communication.

interactive interfaces in which users can continue working while
